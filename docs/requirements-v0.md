# 代敲（TermMate）· 需求 v0

> 本地终端 App，**内置 MCP 是核心亮点**（AI 能直接操作它）
> 本文档由主人（何双斌）口述 + 助手整理，2026-11-19

## 1. 一句话定位
一个**现代终端**（Terminus / Tabby 那一层），但**终端自己就是 MCP 服务器** —— 人和 AI 看同一块屏，AI 能操作，人随时能接管。

## 2. 基础能力（必须有，不是加分项）

### 2.1 本地终端
- 多标签页（Tab）
- 分屏（水平 / 垂直）
- GPU 渲染，低延迟、低内存
- 命令历史、搜索、复制粘贴（含多行、含鼠标选中即复制）
- 会话断线重连

### 2.2 SSH 主机管理 ⭐ 重点
- **保存服务器 SSH 信息**（主机、端口、用户名、备注、分组/标签）
- **三种认证都要支持**：
  1. **密码**
  2. **私钥**（含 **passphrase** 的私钥，passphrase 必须能记住/缓存，否则每次都问等于没用）
     ✅ 已做：密钥库统一入口 + 粘贴导入时直接输口令；口令进 macOS 钥匙串，连接时自动解锁，
     AI 只能看「存没存」，读不到内容。
  3. **证书**（OpenSSH 证书 / 其他）
- 支持 `ProxyJump`（跳板机）—— 运维场景基本必备
- 支持端口转发（本地 / 远程 / 动态 SOCKS）
- **导入现有 `~/.ssh/config` 与 `known_hosts`**（不能让我重新录一遍主机）
  ✅ 已做：界面「从 ~/.ssh/config 导入」+ MCP `ssh_config_scan` / `ssh_config_import`。
  读 known_hosts 时同时看 `~/.ssh/known_hosts` 和代敲自己的库 —— ssh 已信任过的主机不重复问。
- 主机指纹校验（首次连接提示、记住）
  ✅ 已做：三种判定 —— 一致放行 / 首次见面记下并放行（TOFU，留审计痕迹）/ **指纹变了硬拒**。
  变更时报的是人能看懂的话（现在的指纹、记录里的指纹、怎么处置），不是 russh 那句干巴巴的 UnknownKey。
  清记录用 MCP `host_key_forget` 或界面，**只动代敲自己的库，绝不改用户的 ~/.ssh**。

### 2.3 SFTP
- 与 SSH 会话共用同一套主机配置（同样的密码/密钥/passphrase 复用）
- 图形化双栏：本地目录 ⇄ 远程目录
- 上传 / 下载 / 拖拽、断点续传、批量传输队列
- 常用操作：新建目录、删除、重命名、改权限（chmod）、查看大小

## 3. 凭据安全（设计红线，不能妥协）
- **凭据一律进 macOS Keychain**（系统钥匙串），**不落明文配置文件**
- **AI 永远看不到凭据**：AI 只能引用**配置名**（例如"连接 prod-web"），主机、端口、密码、私钥、passphrase **一律不进模型上下文、不进日志**
- **密钥口令**：带口令的私钥，口令只进 macOS 钥匙串；AI 侧只有 `key_passphrase_forget`（清掉）和 `key_list` 里的「已存/未存」状态，**没有读、没有写**。
- ~~危险命令（`rm -rf` / `sudo` / `dd` / `mkfs` / `shutdown` 等）默认需显式确认~~
  **主人已取消这条**（"现在模型也没那么傻"）：MCP 的 `exec` 等工具不做危险命令拦截、不加确认门，
  AI 调什么就执行什么。人的防线是「同一块屏 + 全量审计留痕 + 随时能接手」，不是事前确认框。
  （界面上人工点删除/清密码仍然有确认框，那是防误触，和这条不是一回事。）
- **可审计**：谁（人还是 AI）、什么时候、哪台主机、跑了什么命令，全部留痕

## 4. MCP 工具面（第一版，先少而稳）
- 列出 / 新建 / 切换会话与标签
- `exec`：在指定会话执行命令，**读回完整输出**（含退出码、去 ANSI 的纯文本）
- `wait`：等命令结束（带超时）
- `send_input`：给交互式程序发输入（y/N、方向键、Ctrl-C）
- 读 cwd / 环境变量 / 命令历史
- 引用已保存的 SSH 配置发起连接（**只传配置名，不传凭据**）
- `key_import` / `key_list` / `key_passphrase_forget`：密钥导入、列出（含“口令已存/未存”状态）、清掉存在钥匙串里的解锁口令；**口令本身永远不经过 AI**

## 5. 硬指标
1. **零配置**：装完即用，无需手写 MCP 配置
   ✅ MCP server 随 App 起，硬绑 `127.0.0.1:7391`（不是 0.0.0.0，外网连不进来）。
   界面「连接 AI 客户端」直接给三家客户端的命令/配置片段，复制即用。
2. **多 AI 客户端可同时接入**（Claude Code / Codex / Cursor 同时连）
   ✅ HTTP 通道天然支持并发；另加 **stdio 通道**（`daiqiao-mcp` 桥）给不支持 HTTP 传输的客户端。
   桥只转发 JSON-RPC 到上面那个 HTTP 端点 —— 工具要操作的是运行中那个窗口里的会话，
   所以代敲必须开着。日志只走 stderr，不污染协议通道。
3. **可审计 + 人在场**：人能看到 AI 正在跑什么，并能随时接管
   ✅ 写类操作全留痕（`~/.daiqiao/audit.jsonl`，0600，5MB 轮转）；纯读类工具不记，
   否则日志被刷爆、也没有审计价值（审计要答的是「谁动了什么」，不是「谁看了什么」）。
4. 支持 macOS（优先）；Windows / Linux 待定

### 5.1 人用得下去（第一版之后补的）
- **中文输入**：✅ 每个窗格挂一个贴着光标的隐形 textarea 承接输入法。
  原来整个应用没有可编辑元素，macOS 输入法无处落脚、根本不开组字 —— canvas 加 tabIndex
  只能拿焦点，它不是输入区。组字期间一个字节都不发给 shell（拼音和选词键都不能执行），
  上屏那一下把整段文字一次写进去。`keydown` 里必须看 `isComposing`，否则选词的回车会执行命令。
  **真正根因不是 keydown，而是 mousedown 的默认动作**：不 `preventDefault()` 的话，
  浏览器会把焦点从隐形输入框抢回被点的不可聚焦元素，`ime.focus()` 会被立刻冲掉。
  修复是窗格 `mousedown` 先 `preventDefault()`，再把启动、切窗格、关浮层后的焦点
  链收回输入框；普通字符交给 `input` / `composition` 事件写回 shell，控制键走
  `encodeKey`，窗格的 `composing` 类名作为 WebKit 不设置 `isComposing` 时的兜底。
- **外观**：✅ 字号 9–28 / 等宽字体族 / 6 套配色 / 行高 1.0–2.0 / 光标形状，改完立刻生效。
  程序主动设过光标形状（DECSCUSR，比如 vim 插入模式）时听程序的，外观设置不盖掉它。
  配套 MCP `appearance_get` / `appearance_set` —— 每个人用功能都要有对应的 MCP 工具，
  否则 Agent 操作不了。越界值会被夹回并**明确告知**，主题名写错直接报错并列出可选值
  （静默退回默认会让 AI 以为改成功了）。
